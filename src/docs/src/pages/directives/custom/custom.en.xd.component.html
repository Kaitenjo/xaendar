Custom directives

A custom directive extends CustomDirective and works on the element it is applied to: it listens to it, changes it, measures it, or puts something next to it. The same behavior can then be added to any element of any template with {'@@name'}, without a wrapper component.

The element, the inputs and the hooks

The element is in this.element, typed by the argument of CustomDirective. The inputs are declared with {'@Property'} and read as signals, so this.effect keeps the text of the tooltip in sync: hover Save, click it, and the tooltip changes while it is shown.

onInit runs when the directive starts, onDestroy when the element leaves the template. The effects created with this.effect are disposed on their own, right after onDestroy; the rest has to be undone by hand. This directive appends its tooltip to the body, outside the element, so it removes it in onDestroy: otherwise a tooltip shown while its element is removed would stay on the page.

Outputs

A directive declares outputs with {'@Event'}, like a component. It has no element of its own: its events are dispatched on the element it is applied to, and the template listens to them inside the parentheses of the directive.

The directive listens to the whole document, and emits outside when the pointer is pressed out of its element. The check uses composedPath() instead of target: the page is made of shadow roots, and the target of an event seen from the document is the outermost host, never the element inside it.

Here the output carries a detail, and $event is the CustomEvent with the size. The type of the output is written inline, for the reason explained in Outputs.

The parentheses also accept native events: they are added to the element as if they were written on the tag.

SVG elements

The argument of CustomDirective can be any element type. A directive meant for SVG circles gets the SVG API of the circle, such as its animated radius, without casts.

Edge cases

A directive starts once the element has its attributes and is in the document, but before its children are rendered: onInit sees the id and the bound label, yet no list item, and the items appear a microtask later. Code that needs the children can wait for a microtask, or watch them with a MutationObserver.

Unlike a component, a directive receives its inputs before onInit: the label is already first, not the default. A child component, instead, still has its defaults in its own onInit, as shown in Inputs.

The element and the context of the directive are set after the constructor. There, this.element is undefined and this.effect throws: the setup belongs in onInit.

A directive can be applied once to the same element. Its inputs are checked like those of a component: unknown names and wrong types are compile errors.

API summary

MemberDescription
elementThe element the directive is applied to, available from onInit.
onInit()Runs once the inputs are bound and the element is in the document, before its children are rendered.
onDestroy()Runs when the element leaves the template, before the effects are disposed.
effect(fn, options?)An effect disposed with the directive; returns a function disposing it earlier.
