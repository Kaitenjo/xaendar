Installation

Create a project with the xd command line tool, or add Xaendar to an existing Vite project by hand. Either way you end up with the same four ingredients: the runtime packages, the decorators transform, the Xaendar Vite plugin and the signals polyfill.

Create a project with the CLI

xd new creates the folder, writes the files below and runs npm install. npm start runs xd start, which serves the application on port 4200 and rebuilds it as you edit; npm run build runs xd build, which writes the production bundle in dist.

Three files deserve a closer look.

index.html

The page loads two module scripts, in this order. signals.ts installs the global Signal object that {'@xaendar/core'} needs as soon as it is evaluated; main.ts imports the components.

main.ts

A component exists in the browser only after its class has been evaluated: {'@WebComponent'} then registers it with customElements.define(). Every component and directive your pages use must be imported, directly or indirectly, by the entry point.

Add Xaendar to a project by hand

  1. Install the runtime packages and the build tooling.
  2. Register the decorators transform and the Xaendar plugin in the Vite configuration, in this order.
  3. Configure TypeScript. Xaendar uses standard decorators and the accessor keyword, so do not enable experimentalDecorators. The plugin type-checks the templates with the tsconfig.json found in the directory Vite is started from.
  4. Load signals.ts before your entry point, as in the index.html above.

Your first component

A component is a class extending CustomElement, decorated with {'@WebComponent'}, plus a template and an optional stylesheet. The file names matter: the plugin only compiles classes declared in files ending with .xd.component.ts.

Continue with the Essentials for a quick tour, or follow the tutorial to build a small application step by step.

Keep signals.ts as a separate module script placed before main.ts, or make it the very first import of main.ts: modules are evaluated in import order.

The {'@import'} statement of a template is only read by the compiler, to type-check the bindings. If the class is never imported by your JavaScript, the custom element is never defined: the browser keeps an empty unknown element and reports no error.

If a parent renders while a child it uses is still undefined, the bindings of the child are set as plain string attributes: once the child is defined, its inputs hold their default values until a bound signal changes again. Import the leaf components first, or append the root element only once every module has been imported, as this site does. See Selectors and registration.
