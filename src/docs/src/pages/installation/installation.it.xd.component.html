Installazione

Crea un progetto con lo strumento a riga di comando xd, oppure aggiungi Xaendar a mano a un progetto Vite esistente. In entrambi i casi servono gli stessi quattro ingredienti: i pacchetti di runtime, la trasformazione dei decorator, il plugin Vite di Xaendar e il polyfill dei signal.

Creare un progetto con la CLI

xd new crea la cartella, scrive i file qui sotto ed esegue npm install. npm start esegue xd start, che serve l’applicazione sulla porta 4200 e la ricompila a ogni modifica; npm run build esegue xd build, che scrive il bundle di produzione in dist.

Tre file meritano uno sguardo più da vicino.

index.html

La pagina carica due script modulo, in quest’ordine. signals.ts installa l’oggetto globale Signal di cui {'@xaendar/core'} ha bisogno appena viene valutato; main.ts importa i componenti.

main.ts

Un componente esiste nel browser solo dopo che la sua classe è stata valutata: a quel punto {'@WebComponent'} lo registra con customElements.define(). Ogni componente e direttiva usati dalle pagine deve essere importato, direttamente o indirettamente, dall’entry point.

Aggiungere Xaendar a mano

  1. Installa i pacchetti di runtime e gli strumenti di build.
  2. Registra la trasformazione dei decorator e il plugin di Xaendar nella configurazione di Vite, in quest’ordine.
  3. Configura TypeScript. Xaendar usa i decorator standard e la parola chiave accessor: quindi non abilitare experimentalDecorators. Il plugin verifica i tipi dei template con il tsconfig.json che trova nella cartella da cui viene avviato Vite.
  4. Carica signals.ts prima dell’entry point, come nell’index.html qui sopra.

Il tuo primo componente

Un componente è una classe che estende CustomElement, decorata con {'@WebComponent'}, più un template e un foglio di stile opzionale. I nomi dei file contano: il plugin compila solo le classi dichiarate in file che terminano con .xd.component.ts.

Prosegui con i Fondamenti per un giro veloce, oppure segui il tutorial per costruire passo passo una piccola applicazione.

Casi limite

{'@xaendar/core'} legge Signal.subtle mentre i suoi moduli vengono valutati. Se loadSignals() non è ancora stato eseguito, l’applicazione si ferma prima di renderizzare qualsiasi cosa:

Tieni signals.ts come script modulo separato, posto prima di main.ts, oppure rendilo il primissimo import di main.ts: i moduli vengono valutati nell’ordine degli import.

L’istruzione {'@import'} di un template viene letta solo dal compilatore, per verificare i tipi dei binding. Se la classe non viene mai importata dal tuo JavaScript, il custom element non viene mai definito: il browser mantiene un elemento sconosciuto e vuoto, senza segnalare errori.

Se un padre renderizza mentre un figlio che usa non è ancora definito, i binding del figlio vengono impostati come semplici attributi stringa: una volta definito il figlio, i suoi input mantengono i valori di default finché un signal legato non cambia di nuovo. Importa prima i componenti foglia, oppure aggiungi l’elemento radice solo dopo aver importato tutti i moduli, come fa questo sito. Vedi Selettori e registrazione.

Gli errori di un template vengono stampati, ma xd build termina comunque con exit code 0. Il componente il cui template è fallito finisce nel bundle senza funzione di render, e lancia un errore quando viene connesso: MyAppRootComponent does not seems to have a Render Function.
