Rendering HTML

An interpolation always creates a text node, and a binding on a native element always sets an attribute. A string of HTML therefore shows up as text, which is the safe default. Rendering it as markup takes a directive that sets innerHTML.

A directive for innerHTML

exInnerHtml writes its input into innerHTML from an effect, so the preview follows every keystroke. The Markdown converter escapes the whole source before adding its own tags: the HTML typed in the editor comes out as text, and the only markup in the result is the one the converter writes.

The inserted elements live in the shadow root of the component, so its stylesheet styles them: the headings and the code of the preview use the rules of markdown-preview.css.

innerHTML runs the event handlers of the markup it receives: an {''} with an onerror attribute is enough to execute code. HTML from users, or from any source you do not control, must be escaped, as the converter does, or sanitized by a library built for it.

Edge cases

The string is parsed by the browser, not by the compiler: an interpolation inside it is plain text, a listener written as (click) is an ordinary attribute, and no directive is applied. Every change of the input replaces the whole content, so the inserted elements lose their state, such as the focus or a text selection. The directive replaces whatever the element contains, and the children written in the template are rendered right after onInit, as shown in Custom directives. Apply it to an empty element.

API summary

SyntaxResult
{'{ html() }'}The string as text, tags included.
{'@@exInnerHtml(html="{ html() }")'}The string parsed as HTML, updated when it changes.
