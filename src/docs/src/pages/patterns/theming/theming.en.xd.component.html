Theming

The shadow DOM keeps the selectors of the page out of components, but not inherited properties, and custom properties are inherited. A theme is therefore a set of custom properties declared on an ancestor, which the components read with var().

Tokens and parts

The stage sets data-theme from a signal, and its stylesheet declares a set of tokens for each value. The cards declare no theme at all: they read --card-bg, --card-text and --accent, with a fallback for when no theme is set. The accent comes from a color field, bound straight into a style attribute with a template literal.

The second card shows the other way in: its heading is exposed with part="heading", and the parent styles it with ::part(heading). Tokens suit values shared by many components; parts suit the cases where a component lets its users restyle one specific element. Both are described in Styling.

A theme for the whole application

This site keeps the theme in a module signal, writes it on {''}, and stores the choice. The tokens are declared on :root in the global stylesheet, so every component inherits them.

Components render after the scripts of the application are loaded. A small inline script in index.html applies the stored theme, or the one preferred by the system, before the first paint, so the page never flashes in the wrong colors.

Edge cases

A shadow root has no root element, so :root in the stylesheet of a component matches nothing. Tokens local to a component go on :host.

A theme cannot restyle the inside of a component with ordinary selectors. What the component does not read from a custom property, or expose as a part, stays as the component defines it.
