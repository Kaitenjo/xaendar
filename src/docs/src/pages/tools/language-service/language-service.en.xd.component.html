Language service and VS Code

The repository contains a VS Code extension for templates, made of two parts: a grammar for syntax highlighting, and a client starting {'@xaendar/language-server'}, meant to bring the checks of the compiler into the editor. Both are at an early stage: this page describes what they do today.

The repository has no packaging step for the Marketplace, and the language server does not report diagnostics or offer completions yet. The compiler messages are available in the terminal of xd start, as described in Build and Vite plugin.

Running the extension

The extension is built from the repository and started in a development window of VS Code.

It activates in workspaces containing .xd.component.html files, associates them with the language Xaendar Template, and starts the server over IPC.

Syntax highlighting

The grammar is injected into the HTML grammar of VS Code: templates keep the highlighting of HTML, and some Xaendar constructs get their own colors.

The language server

The server is designed to compile each template as it is edited, with the same type-check shim used by the Vite plugin, and to turn the result into editor features:

  • Diagnostics: after 300 ms without typing, the semantic errors of TypeScript on the template, at their position; syntax errors of the template at its first line.
  • Completions: the completions of TypeScript inside template expressions, triggered by ., {'\x7B'} and (.

Edge cases

To compile a template, the server must know the component class using it. The index mapping templates to components is built at startup, but the code filling it is disabled: every template is skipped, so neither diagnostics nor completions are produced. The grammar expects {'{{ expr }}'}, a syntax that Xaendar does not use. Interpolations written as {'{ expr }'} in text, and directives, keep the colors of plain HTML. The server announces hover support but implements no hover, and starts five seconds after the extension.
