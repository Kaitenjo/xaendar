Language service e VS Code

Il repository contiene un’estensione di VS Code per i template, fatta di due parti: una grammatica per l’evidenziazione della sintassi, e un client che avvia {'@xaendar/language-server'}, pensato per portare i controlli del compilatore nell’editor. Entrambe sono in una fase iniziale: questa pagina descrive cosa fanno oggi.

Il repository non ha un passaggio di pacchettizzazione per il Marketplace, e il language server non segnala ancora diagnostica né offre completamenti. I messaggi del compilatore sono disponibili nel terminale di xd start, come descritto in Build e plugin Vite.

Avviare l’estensione

L’estensione viene compilata dal repository e avviata in una finestra di sviluppo di VS Code.

Si attiva nei workspace che contengono file .xd.component.html, li associa al linguaggio Xaendar Template, e avvia il server via IPC.

Evidenziazione della sintassi

La grammatica viene iniettata in quella HTML di VS Code: i template mantengono l’evidenziazione dell’HTML, e alcuni costrutti di Xaendar ricevono colori propri.

Il language server

Il server è progettato per compilare ogni template mentre viene modificato, con lo stesso shim di type check usato dal plugin Vite, e per trasformarne il risultato in funzionalità dell’editor:

  • Diagnostica: dopo 300 ms senza digitare, gli errori semantici di TypeScript sul template, nella loro posizione; gli errori di sintassi del template sulla sua prima riga.
  • Completamenti: i completamenti di TypeScript dentro le espressioni del template, attivati da ., {'\x7B'} e (.

Casi limite

Per compilare un template, il server deve conoscere la classe componente che lo usa. L’indice che associa i template ai componenti viene costruito all’avvio, ma il codice che lo riempie è disattivato: ogni template viene saltato, quindi non si ottengono né diagnostica né completamenti. La grammatica si aspetta {'{{ expr }}'}, una sintassi che Xaendar non usa. Le interpolazioni scritte come {'{ expr }'} nel testo, e le direttive, mantengono i colori dell’HTML semplice. Il server dichiara il supporto all’hover ma non lo implementa, e parte cinque secondi dopo l’estensione.
