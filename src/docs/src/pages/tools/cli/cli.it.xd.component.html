CLI

xd, da {'@xaendar/cli'}, crea progetti e componenti, e avvia Vite con i plugin di cui Xaendar ha bisogno. Non fa altro: vite.config.ts resta una normale configurazione di Vite.

xd new

Il nome del progetto viene usato per la cartella, per package.json e per il componente radice, {'-root'}. I file generati sono descritti in Installazione. Il comando si ferma se la cartella esiste e non è vuota.

xaendar.json registra le impostazioni del progetto. Oggi contiene solo l’estensione scelta con --style.

xd start e xd build

xd start (o xd s) avvia il dev server di Vite, xd build (o xd b) una build di produzione. Entrambi leggono vite.config.ts dalla cartella corrente e vi aggiungono due plugin: Babel, per compilare i decoratori, e il plugin Xaendar, per compilare template e stili. I dettagli sono in Build e plugin Vite. Tutto il resto, come la porta, la cartella radice o quella di output, viene dalla configurazione di Vite.

xd component

Il comando crea una cartella con il nome del componente, con la classe, il template, il foglio di stile e una spec. Il nome viene usato come selettore, quindi deve essere un nome valido per un custom element; la classe prende lo stesso nome in PascalCase.

Ricorda di importare il nuovo componente: in main.ts, o con un glob, così viene definito, e nei template che lo usano, con {'@import'}.

Casi limite

Il comando dei componenti dovrebbe stare in un gruppo generate, con l’alias g, ma finisce registrato al livello principale. Usa xd component o xd c.

I nomi dei componenti vengono controllati prima di scrivere qualsiasi file.

Il nome di un progetto, invece, viene controllato solo quando si genera il componente radice, dopo che gli altri file sono già stati scritti.

xd new accetta scss, less e styl, ma il plugin compila solo file .css. xd component, dal canto suo, ignora xaendar.json e scrive sempre un file .css.

Il package.json generato esegue Vitest, che non conosce né la trasformazione dei decoratori né il plugin Xaendar: la spec del componente radice fallisce prima di partire. Per testare i componenti serve una configurazione di Vitest con gli stessi plugin e un ambiente DOM.

I pacchetti pubblicati su npm come 0.12.0 precedono l’API descritta in questo sito: il loro {'@xaendar/core'} esporta BaseWebComponent invece di CustomElement. Un progetto creato da una CLI compilata dal repository li installa, e la sua build fallisce. Fino al prossimo rilascio, lavora dentro il repository, come fa questo sito.

Un template che non compila viene segnalato, ma la build prosegue e termina con successo: il componente arriva nel bundle senza funzione di render. Controlla l’output nelle pipeline automatiche.
