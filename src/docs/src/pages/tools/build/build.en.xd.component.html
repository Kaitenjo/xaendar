Build and Vite plugin

Templates and styles are compiled ahead of time by xaendarPlugin(), from {'@xaendar/build-tools'}. The CLI adds it to Vite on its own; a project driving Vite directly adds it to its configuration, after the transform of the decorators.

Configuration

The order matters. Babel compiles the standard decorators first, and the plugin then works on its output: it looks for the static blocks Babel generates in each decorated class, and adds its own registration before them. With the plugins in the wrong order, every component fails with the message shown in Installation.

The plugin takes no options. It reads tsconfig.json from the folder Vite is started from, and uses its compiler options, including the strict ones, to type-check the templates.

What the plugin does

Only files whose name ends with .xd.component.ts are compiled. For each component class in such a file, the plugin reads the options of {'@WebComponent'}, validates and claims the selector, type-checks the template against the class, and adds to the module two imports from virtual modules: the render function of the template and the stylesheet.

Each template becomes a module exporting its render function. The signals parameter in its id lists the members of the class recognized as signals, which decide which bindings are reactive. Each CSS file becomes a module exporting a CSSStyleSheet: components pointing to the same file share the same sheet.

Comments are removed from the CSS. In vite build, the CSS is also minified with Lightning CSS, unless the Vite configuration turns CSS minification off.

Errors

Errors in a template are printed by the dev server and by the build, with the position in the template and the excerpt involved. The component they belong to is left without its render function, and throws when it is connected. The Error encyclopedia lists the messages.

Dev server

The plugin watches, for each component, its template, its stylesheet, the classes it extends and the components its template imports. Editing any of them recompiles what depends on it, and the page reloads.

Edge cases

Type-check and syntax errors are logged, but the build ends with exit code 0, and the broken component is in the bundle. Errors of the code generator, such as a signal declared twice by a class and its base, are the exception: they stop the build. See CLI for a check to add to automated pipelines.

The plugin type-checks templates, not the TypeScript of the classes: a member clashing with a property of HTMLElement, such as title or remove, reaches the bundle unnoticed. Run tsc --noEmit as well. The dev server caches the inputs and the outputs of each component and directive. After changing their types, the templates using them may still be checked against the old ones until the server restarts. tsconfig.json is read from the folder Vite is started from, not from the folder of vite.config.ts. Start xd or Vite from the root of the project. Only .css files can be used as styleUrl, and {'@import'} rules inside them are dropped by the browser, since constructed stylesheets do not support them. See Styling.
