Build e plugin Vite

Template e stili vengono compilati in anticipo da xaendarPlugin(), di {'@xaendar/build-tools'}. La CLI lo aggiunge a Vite da sola; un progetto che usa Vite direttamente lo aggiunge alla sua configurazione, dopo la trasformazione dei decoratori.

Configurazione

L’ordine conta. Babel compila prima i decoratori standard, e il plugin lavora poi sul suo output: cerca i blocchi statici che Babel genera in ogni classe decorata, e aggiunge la sua registrazione prima di essi. Con i plugin nell’ordine sbagliato, ogni componente fallisce con il messaggio mostrato in Installazione.

Il plugin non ha opzioni. Legge tsconfig.json dalla cartella da cui viene avviato Vite, e ne usa le opzioni del compilatore, comprese quelle strict, per il type check dei template.

Cosa fa il plugin

Vengono compilati solo i file il cui nome termina con .xd.component.ts. Per ogni classe componente in un file del genere, il plugin legge le opzioni di {'@WebComponent'}, valida e riserva il selettore, esegue il type check del template rispetto alla classe, e aggiunge al modulo due import da moduli virtuali: la funzione di render del template e il foglio di stile.

Ogni template diventa un modulo che esporta la sua funzione render. Il parametro signals nel suo id elenca i membri della classe riconosciuti come signal, che decidono quali binding sono reattivi. Ogni file CSS diventa un modulo che esporta un CSSStyleSheet: i componenti che puntano allo stesso file condividono lo stesso foglio.

I commenti vengono rimossi dal CSS. In vite build, il CSS viene anche minificato con Lightning CSS, a meno che la configurazione di Vite non disattivi la minificazione del CSS.

Errori

Gli errori di un template vengono stampati dal dev server e dalla build, con la posizione nel template e l’estratto coinvolto. Il componente a cui appartengono resta senza funzione di render, e lancia un errore quando viene connesso. L’Enciclopedia degli errori elenca i messaggi.

Dev server

Il plugin osserva, per ogni componente, il suo template, il suo foglio di stile, le classi che estende e i componenti importati dal suo template. Modificare uno di essi ricompila ciò che ne dipende, e la pagina si ricarica.

Casi limite

Gli errori di type check e di sintassi vengono registrati, ma la build termina con exit code 0, e il componente rotto finisce nel bundle. Gli errori del generatore di codice, come un signal dichiarato due volte da una classe e dalla sua base, sono l’eccezione: fermano la build. Vedi CLI per un controllo da aggiungere alle pipeline automatiche.

Il plugin controlla i template, non il TypeScript delle classi: un membro in conflitto con una proprietà di HTMLElement, come title o remove, arriva nel bundle senza segnalazioni. Esegui anche tsc --noEmit. Il dev server tiene in cache input e output di ogni componente e direttiva. Dopo averne cambiato i tipi, i template che li usano possono essere ancora controllati con quelli vecchi finché il server non viene riavviato. tsconfig.json viene letto dalla cartella da cui parte Vite, non da quella di vite.config.ts. Avvia xd o Vite dalla radice del progetto. Come styleUrl si possono usare solo file .css, e le regole {'@import'} al loro interno vengono scartate dal browser, perché i fogli di stile costruiti non le supportano. Vedi Stili.
