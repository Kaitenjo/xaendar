Computed signals

computed(fn) creates a read-only signal whose value is derived from other signals. It tracks what fn reads, evaluates lazily and caches the result until a dependency changes.

Lazy and cached

A computed signal does nothing when it is created. The first read runs fn; later reads return the cached value, until one of the signals fn read changes. Even then nothing runs immediately: the value is only marked stale, and recomputed by the next read.

While the full name is shown, reading it three times costs nothing and each rename costs one evaluation. Hide it: renames now cost nothing at all, because nobody reads the value. Showing it again evaluates it once.

Dynamic dependencies

Dependencies are collected again at every evaluation: a signal read in a branch that was not taken is not a dependency. Here title is only a dependency while showTitle is true.

Glitch-free updates

When several computed signals depend on the same source, a change is propagated in topological order: a signal is evaluated only after the signals it depends on, and only once. No consumer ever sees an old value mixed with a new one.

Errors

If fn throws, the error is cached like a value: every read throws it again, without running fn, until a dependency changes. The next successful evaluation clears it.

Options and this

computed(fn, options) accepts the equals option: when the new result equals the cached one, the consumers are not told that anything changed. Inside a regular function, this is the underlying Signal.Computed; arrow functions keep the this of the class.

Edge cases

The cache only holds while something — an effect, a template binding — depends on the computed signal. Hide the full name in the first example and press “Read it 3 times”: three reads, three evaluations. Avoid reading an expensive computed signal repeatedly from plain code; read it once into a variable. A computed signal can run at unpredictable times — or not at all, if nobody reads it. Do not write signals or perform side effects in fn: use an effect. The function returned by computed() has get() but no set() or update(). To change the value, change its dependencies. The options type accepts watched and unwatched, but computed signals ignore them: only writable signals call them. See Signal options.
