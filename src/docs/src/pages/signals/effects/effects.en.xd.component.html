Effects

An effect is a function that runs whenever the signals it read change. Effects are how signals reach the outside world: logging, storage, timers, canvas drawing, third-party libraries. Template bindings are effects too.

Creating an effect

effect(fn, options?) runs fn immediately and synchronously, recording the signals it reads. When any of them changes, fn runs again — not immediately, but in a microtask. It returns a function that disposes the effect.

Batching

All the changes made in the same synchronous block cause a single run, which sees the final values. The run is scheduled as soon as a dependency changes, and happens even if the values end up equal to the ones of the previous run.

Effects of a component

Components and directives have their own this.effect(fn, options?). It works like effect(), but the effect is disposed automatically when the component leaves the page. Create it in onInit or afterRender. A standalone effect() lives until its disposer is called, whatever happens to the component that created it.

Add the child, wait a few seconds and remove it: the effect created with this.effect() stops, the standalone one keeps logging — and keeps the clock ticking — until it is disposed.

Options

  • onBeforeRun runs before every run, the first one included.
  • onAfterRun runs after every run, even when fn throws.
  • onCleanup runs once, when the effect is disposed.

Disposing

Calling the disposer stops the effect and releases every subscription. The disposer of this.effect() can be called any number of times, even after the component is gone; the one of a standalone effect() throws the second time.

Errors

An error thrown by the first run is thrown by effect() itself: the effect is removed and no disposer is returned. An error thrown by a later run escapes the microtask: it is not caught by anything, reaches the global error handler, and the effect keeps reacting to the next changes.

Edge cases

Unlike the cleanup functions of other libraries, onCleanup runs only when the effect is disposed, not before each re-run. To clean up after each run, do it at the beginning of fn or in onBeforeRun. Changing a dependency and changing it back in the same block still schedules a run, as the “a++, a--” button shows. Effects must be idempotent.

Writing signals inside an effect is allowed, but writing one the effect also reads schedules a new run every time: the microtask queue never empties and the page freezes. update() reads without tracking, so it is safe for signals the effect does not otherwise read.

this.effect() works in the constructor, but such an effect is disposed the first time the component is removed, and the constructor does not run again when it is re-inserted. Create effects in onInit. See Lifecycle. The JSDoc of onCleanup says it runs before each re-run, and the README of {'@xaendar/signals'} shows two synchronous writes producing two runs. Both are wrong: the behavior is the one described on this page.

API summary

APIDescription
effect(fn, options?)Runs fn now and after every change of what it read; returns a disposer.
this.effect(fn, options?)Same, disposed with the component or directive. Its disposer is idempotent.
options.onBeforeRunCalled before each run.
options.onAfterRunCalled after each run, even a failed one.
options.onCleanupCalled once, on disposal.
