Advanced: Signal.subtle

Xaendar signals are a thin layer over the TC39 Signals proposal, polyfilled by {'@xaendar/signals'}. The global Signal object exposes the primitives the framework is built on: you rarely need them, but they explain how everything works.

The global Signal object

loadSignals() installs globalThis.Signal once, with Signal.State, Signal.Computed and the Signal.subtle namespace. signal() and computed() wrap a Signal.State and a Signal.Computed in a callable function; effect() combines a Signal.Computed with a Signal.subtle.Watcher.

Watchers

A Watcher is told, synchronously, that one of the signals it watches may have changed. It cannot do anything in its notify callback — every signal is frozen — except scheduling work. That work reads the pending computed signals with getPending(), then calls watch() to be notified again: a watcher notifies once, then waits to be re-armed.

Introspection

Signal.subtle can inspect the live graph: introspectSources, introspectSinks, hasSources, hasSinks, and currentComputed, which returns the computed signal being evaluated, if any. Evaluating a computed signal links it to its sources, in both directions; unwatching it unlinks it again.

Dev mode

In dev mode the polyfill logs the errors thrown inside computed signals, watchers and the watched/unwatched callbacks, and warns about invalid state transitions of the graph. loadSignals installs the global object only once, but applies devMode at every call.

Edge cases

They are typed as Signal.State and Signal.Computed, but they are wrapper functions, and there is no public way to reach the object they wrap. The Signal.subtle API only works with objects created with new Signal.State() and new Signal.Computed(), like the examples above.

watch() on a signal already watched by the same watcher throws Cannot watch a signal that is already being watched; unwatch() on a signal it does not watch throws Cannot unwatch a signal that is not being watched. Both throw while signals are frozen too.
