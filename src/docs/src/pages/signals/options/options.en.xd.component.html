Signal options

The second argument of signal() customizes equality and lets a signal know when it starts and stops being observed.

equals

Decides whether a new value is a change. See Signals for an example; on computed() it decides whether a new result is a change.

watched and unwatched

watched runs when the signal gains its first live dependent — an effect or a template binding, directly or through computed signals. unwatched runs when it loses the last one. They are the place to start and stop whatever feeds the signal: a timer, a subscription, an event listener.

Edge cases

Watch the counters while the clock is displayed: every tick adds one unwatched and one watched. When a dependent re-runs, it unsubscribes from all its sources before subscribing again to the ones it reads; if it is the only dependent, the signal is briefly unwatched. Make the callbacks cheap and idempotent — here the timer is cleared and started again at each tick.

The callbacks run while the reactive graph is being updated, with every signal frozen: reading or writing one throws. Schedule the work instead — queueMicrotask, a timer, an event — as the clock does. computed(fn, options) accepts the same options type, but only equals is used. The {'@Property'} decorator accepts these options plus transform and alias. See Inputs.
