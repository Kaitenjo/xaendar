Template syntax

A Xaendar template is HTML with a handful of additions: interpolations and bindings in braces, events in parentheses, control flow and imports introduced by {'@'}, and directives. The compiler reads it at build time, checks every expression against the class of the component, and turns it into code that creates the DOM and wires each node to the signals it reads.

Stricter than HTML

The browser forgives a lot of HTML; the compiler does not, and each of these mistakes fails the build with the position of the problem:

  • void elements are closed with {'/>'} as in XML, {''}, never left open;
  • closing tags match the opening ones letter by letter, upper case included;
  • attribute values are always in double quotes.

Whitespace

The compiler drops the line breaks of the text, instead of turning them into spaces, and drops the text made only of whitespace, between two tags or two interpolations. Indentation is kept, and the browser collapses it into one space.

  1. the line break disappears, and the two words touch;
  2. the indentation of the second line becomes the space: indent the lines of text you wrap;
  3. the space between two tags is dropped;
  4. {"{' '}"} writes a space that stays;
  5. the space between two interpolations is dropped too;
  6. building the text in one expression keeps it.

Special characters

{'@'}, braces and {'<'} have a meaning in templates, and the compiler does not decode HTML entities: < is shown as written. To show those characters, interpolate a string; for all the others, such as arrows and typographic quotes, write the character itself.

A string may contain braces only in pairs, as in the last row: an unpaired brace inside a string still counts when the compiler looks for the end of the interpolation, hence the \x7B and \x7D escapes.

Edge cases

An {'@'} followed by letters starts a block, so an email address in the text does not compile. Inside attribute values {'@'} is safe.

{'<'} always opens a tag, and the error points somewhere after it. {'>'} is safe.

HTML comments are allowed and are not rendered, but one that is never closed swallows everything after it, without any error.
