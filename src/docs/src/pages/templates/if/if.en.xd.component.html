Conditionals with {'@if'}

{'@if'} renders a block only while its condition is truthy, with optional {'@else if'} and {'@else'} branches. The condition is reactive: it runs again whenever a signal it reads changes, and the block switches branch when the result says so.

Branches

The conditions are tried from the top, and the first truthy one wins. Like text interpolations, conditions are always reactive, even when they call a method. A block can contain anything a template can: elements, text, components and other control flow. Here the branches hold only text, inside one paragraph: a chain whose branches start with the same element hits a bug of the compiler, described in the edge cases.

When a branch is rendered again

The block keeps track of the branch it shows, not of the value of the condition. While the same branch wins, its elements are left alone; when another branch wins, the elements of the old one are removed, with the components inside them, and the new ones are created.

Type some notes, then add guests: the condition runs again at every click, but it stays true, and the field keeps its text. Go down to zero and back: the field is created again, empty. State that must survive belongs in signals, not in the elements of a branch.

Edge cases

Move the slider: on the left the colors are right, but every branch after the first one shows the text of the last branch. The compiler names the elements of the {'@else if'} and {'@else'} branches as if they were siblings of the {'@if'}, so elements with the same tag in the same position share their generated code, with each other and with the siblings of the block. It is a known issue; until it is fixed:

  • switch on a computed signal, as on the right: the branches of {'@switch'} are not affected;
  • keep only text in the branches, as in the first example;
  • write separate {'@if'} blocks with conditions that exclude each other;
  • a plain {'@if'} with one {'@else'} is safe, as long as no sibling of the block has the same tag in the same position.

The functions generated for the inner and the outer block get the same names: the wrong branch is rendered, and the template ends in an endless recursion. Use {'@else if'}, or wrap the inner block in an element.

The space after {'@if'} is required, an {'@else'} must follow a block, and there is no as to name the value of the condition: read it again inside the block, or keep it in a computed signal.

The condition follows JavaScript: 0, '', null, undefined and NaN select the {'@else'} branch. For a count that can be zero, compare it explicitly, as {'guests() > 0'} does.

API summary

SyntaxDescription
{'@if (condition) { … }'}Renders the block while the condition is truthy.
{'@else if (condition) { … }'}Tried when the previous conditions are falsy.
{'@else { … }'}Rendered when no condition is truthy.
