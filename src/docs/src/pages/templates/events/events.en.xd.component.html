Event listeners

An attribute whose name is in parentheses listens to the event of that name and calls a method of the component. The handler is always one call to a method, with simple arguments: the logic lives in the class, where it can be read, typed and tested.

Calling a method

The arguments can be:

  • literals: strings, numbers, true, false, null;
  • $event, the event itself, in any position;
  • members of the component and variables of an {'@for'}, with their properties, as in color.id;
  • a signal without the call, which passes the signal itself: bump changes whichever counter it receives.

The template is type-checked: $event has the type of the event, a MouseEvent for click or a KeyboardEvent for keydown, and each argument must fit the parameter of the method.

What a handler cannot contain

Edge cases

Templates have no event modifiers: (keydown.enter) listens to an event whose name is literally keydown.enter, which the browser never dispatches, and the first counter never moves. Filter the key in the method, as the second field does. The same goes for preventDefault() and stopPropagation(): call them on $event.

A handler calling a method of a member compiles, but fails at the first event.

 $event can only be passed whole: $event.target or $event.detail in a handler do not compile. Read them in the method. On the tag of a component only the events it declares with {'@Event'} can be bound, not the native ones; on native elements only the native ones. See the edge cases of Outputs.
