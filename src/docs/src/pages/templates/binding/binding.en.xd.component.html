Attribute and property binding

An attribute whose value is an expression in braces is bound: the compiler sets it when the element is created, and again whenever the value changes. On a native element a binding sets an attribute; on the tag of a component it sets the input of the same name.

Binding attributes

The whole value has to be one expression: a template literal when you need text around it. The value is converted to a string and written with setAttribute, so class and style are bound like any other attribute, as shown in Styling.

Which expressions are reactive

Attributes follow a stricter rule than text. The compiler decides at build time whether an attribute can change, by looking for the signal members the expression names: members initialized with a function of {'@xaendar/core/signals'}, inputs and queries. An attribute that names none is set once.

percentOf() reads the level, but it is a method: the compiler cannot see what it reads, so the first meter keeps the value of the first render. The same method in the text below is reactive, because text interpolations always are. Move the logic of attribute bindings into computed signals. The rule for members that hold a signal created elsewhere is in Shared state.

Binding the inputs of components

On the tag of a component the same syntax sets an input, with values of any type, checked against the type of the input. A static value is always a string. See Inputs.

Edge cases

A boolean attribute counts by its presence, not its value: disabled="false" still disables the button, so the first one is always disabled. Use a conditional binding, which adds and removes the attribute.

Type in both fields, then reset. A binding sets the value attribute, which is only the initial value of the field: once the user has typed, the field shows its value property, and the first field is not cleared. The second field sets the property from an effect. The Forms pattern wraps this in a directive.

Braces count only when they hold the whole value: a value mixing text and braces is static, and the braces end up in the attribute.

An attribute bound to null or undefined is not removed: it becomes the text "null" or "undefined". To remove an attribute, bind it conditionally.

An attribute can be static or bound, not both, even when one of the two is conditional.

 A static disabled written without a value is set to "true": the element is disabled, as expected, but the attribute does not read "" as in HTML.

API summary

SyntaxResult
name="text"A static attribute.
{'name="{ expression }"'}An attribute set with String(value), again whenever a signal member it names changes.
{'name="{`…${expression}…`}"'}The same, with text around the value.
{'@if (condition) { name }'}An attribute present only while the condition holds.
{'input="{ expression }"'} on a componentSets the input, with the value as it is.
