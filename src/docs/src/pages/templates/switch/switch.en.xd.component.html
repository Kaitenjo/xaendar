Branching with {'@switch'}

{'@switch'} compares one value with a list of cases and renders the block of the first one that matches, or the {'@default'} block when none does. It reads better than a chain of {'@else if'} when every branch tests the same value.

Cases

The comparison is strict, ===: {"@case (1)"} does not match the string '1'. Cases written one after the other without a block share the block of the last one, as pending and paid do. As with {'@if'}, the block is rendered again only when another case wins.

A {'@switch'} on a computed signal is also the way around a bug of {'@else if'} chains whose branches start with the same element: see the edge cases of {'@if'}.

Edge cases

The blocks are tried in the order they are written, and {'@default'} always matches: written first, it hides every case after it. Keep it last.

The expression of the switch runs once for each case it is compared with: once for Monday, five times for the weekend. A method with side effects, or a slow one, runs as many times. Switch on a signal or a computed signal, which read their cached value. This is listed in Known issues.

The value of a case cannot read the members of the component. Compare with literals, or move the logic into a computed signal that returns one of them.

API summary

SyntaxDescription
{'@switch (value) { … }'}Compares the value with the cases, in order.
{"@case ('a') { … }"}Rendered when the value is === 'a'.
{"@case ('a') @case ('b') { … }"}One block for several values.
{'@default { … }'}Rendered when no case matches. Keep it last.
