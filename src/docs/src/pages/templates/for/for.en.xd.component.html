Lists with {'@for'}

{'@for'} renders its block once for each item of an array, or a number of times. Each row is identified by a key, given by track: when the array changes, the rows whose key is still there are kept, moved if needed, and only the others are created or removed.

Items, keys and context

Inside the block, $index, $first, $last, $even and $odd describe the position of the row. They are signals: call them, and they update when rows are added or removed before, as the stripes show, without rendering the row again. position = $index gives one of them another name, which is the way to reach the index of an outer loop from an inner one.

The key is an expression of the item: an identifier, or the item itself with track task. Without track the item itself is the key.

Repeating a number of times

A number instead of an array repeats the block: {'@for (5)'} without a variable, or {'@for (n of count())'} with n going from 0 to count() - 1. The number can come from a signal, and the rows follow it.

Nested loops

The inner loop sees the variables of the outer one. Both have their own $index, and the inner one hides the outer: the alias r = $index keeps the index of the row reachable from the cells.

Empty lists

There is no {'@empty'} block: wrap the loop in an {'@if'} on the length of the array.

Edge cases

Type notes next to Ada in both columns, then move the last person to the top. Tracked by identifier, the row of Ada moves with its field and its notes. Tracked by index, nothing changes at all: the item of a row is fixed when the row is created, so the rows keep their old names. Track by a stable identifier, never by index.

For the same reason, replacing an item with a new object with the same key leaves its row as it was: the first column keeps showing apple. Tracking the item itself creates a new row for the new object, losing the state of the old one. When items change in place, keep the changing values in signals inside the items, as in the third column: the text reading them updates without touching the row. This is listed in Known issues.

Keys must be unique. With a duplicate the rows stop matching the array, and every change makes it worse: press the button a few times. Nothing reports it.

Arrays and numbers only: a Set, a Map or a string must be converted to an array first, for example with [...set] in a computed signal. There is no $count: use the length of the array. The expression of track can only read the item and the context, not the members of the component. A negative number renders nothing.

API summary

SyntaxDescription
{'@for (item of items(); track item.id) { … }'}A row for each item, identified by its key.
{'@for (item of items()) { … }'}The item itself is the key.
{'@for (5) { … }'}, {'@for (n of count()) { … }'}Repeats the block, with n from 0.
$index(), $first(), $last(), $even(), $odd()The position of the row, as signals.
{'…; track item.id; i = $index'}An alias for a context variable.
