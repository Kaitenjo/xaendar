Importing components

{'@import'} tells the compiler which components and directives a template uses. It works only at build time: the compiler reads the classes it names to know their selectors, inputs and events, and checks every use against them. It does not load anything in the browser.

Forms

The syntax is the one of a named import in TypeScript: one or more class names in braces, and a path in single or double quotes. A file can declare several components, and one {'@import'} brings all those the template needs. Imports can appear anywhere in the template; keeping them at the top makes them easy to find.

The path is relative to the template, and it is resolved as a file, with or without the .ts extension, or as a folder with an index.ts. Packages and the path aliases of tsconfig.json are not resolved yet.

Importing is not registering

The browser knows a component only once the file declaring its class has run, which defines the custom element. Every component must therefore also be imported in TypeScript somewhere, usually all at once in main.ts. See Selectors and registration, which also shows the error for a component used without {'@import'}.

Edge cases

With a path that does not resolve, a default import or a name the file does not declare, the template does not compile. Imports nobody uses are not reported.

A component published in a package, or reached through a path alias, cannot be imported in a template yet: the resolver only follows relative paths, and the class must be declared in the file it points to. {'@import'} only accepts classes of components and directives. The types used by their inputs are not imported with them, so the inputs must use inline types. See the edge cases of Inputs.
