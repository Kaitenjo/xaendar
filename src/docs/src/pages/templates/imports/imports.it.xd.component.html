Importare componenti

{'@import'} dice al compilatore quali componenti e direttive usa un template. Funziona solo a build time: il compilatore legge le classi che nomina per conoscerne selettori, input ed eventi, e controlla ogni utilizzo rispetto a esse. Non carica nulla nel browser.

Forme

La sintassi è quella di un import con nome in TypeScript: uno o più nomi di classe tra graffe, e un percorso tra apici singoli o doppi. Un file può dichiarare più componenti, e un solo {'@import'} porta tutti quelli che servono al template. Gli import possono stare in qualsiasi punto del template; tenerli in cima li rende facili da trovare.

Il percorso è relativo al template, e viene risolto come file, con o senza l’estensione .ts, oppure come cartella con un index.ts. I pacchetti e gli alias di percorso del tsconfig.json non vengono ancora risolti.

Importare non è registrare

Il browser conosce un componente solo dopo che il file che ne dichiara la classe è stato eseguito, il che definisce il custom element. Ogni componente va quindi importato anche in TypeScript da qualche parte, di solito tutti insieme in main.ts. Vedi Selettori e registrazione, che mostra anche l’errore per un componente usato senza {'@import'}.

Casi limite

Con un percorso che non si risolve, un import di default o un nome che il file non dichiara, il template non compila. Gli import che nessuno usa non vengono segnalati.

Un componente pubblicato in un pacchetto, o raggiunto tramite un alias di percorso, non si può ancora importare in un template: il resolver segue solo percorsi relativi, e la classe deve essere dichiarata nel file a cui puntano. {'@import'} accetta solo classi di componenti e direttive. I tipi usati dai loro input non vengono importati con esse, quindi gli input devono usare tipi inline. Vedi i casi limite di Input.
