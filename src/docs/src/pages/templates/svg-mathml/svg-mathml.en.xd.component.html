SVG and MathML

SVG and MathML can be written straight into templates. The compiler knows which elements belong to them and creates each one in the right namespace, so everything a template does with HTML works with them too: bindings, events, control flow, components around them.

SVG

The bars are real SVGRectElements: an {'@for'} renders them, their geometry comes from a computed signal, and their listeners are typed as for HTML, with a MouseEvent for mouseenter. Names written in camelCase, such as viewBox or linearGradient, are kept as they are, as SVG requires. Styles apply as usual: the stylesheet of the component colors the bars and the hovered one.

MathML

The elements inside {''} are MathMLElements, rendered by the browser. Interpolations inside {''} and {''} update like any text: move the slider and only the numbers change.

Edge cases

In SVG, {''} holds HTML. The compiler keeps creating the children in the SVG namespace, so the paragraph is an unknown SVG element and the browser does not render it. Place HTML over the SVG with CSS positioning, or create the content of the {''} in code. This is listed in Known issues.

As for HTML, a binding sets an attribute with setAttribute: numbers become strings, which SVG accepts for geometry. Properties of SVG elements, such as animated values, have to be set in code.
