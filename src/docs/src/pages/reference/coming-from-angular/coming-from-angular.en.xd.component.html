Coming from Angular

Xaendar borrows much of its vocabulary from Angular: decorators, signals, a control flow with {'@if'} and {'@for'}, structural directives. Under the names, the model is different: every component is a real custom element with a shadow root, templates are compiled into direct updates of single nodes, and there is no framework around them: no modules, no injector, no zone.

What works differently

  • Inputs arrive after the first render. A child renders as soon as it is connected, and its inputs are set right after: onInit sees the defaults. Read inputs reactively. See Inputs.
  • Bindings set attributes. On native elements a binding calls setAttribute: a value stops mattering once the user types, and disabled="{'\x7B'} false {'\x7D'}" still disables. See Binding and Forms.
  • Moving an element re-renders it. Disconnection destroys the content of the shadow root, and the next connection renders it again. See Lifecycle.
  • Templates are strict. Listeners call one method, expressions cannot assign or create objects, and a few characters must be escaped. See the cheat sheet.
Dependency injection, a router, a forms module, an HTTP client, two-way binding, event modifiers such as (keydown.enter), {'@defer'}, {'@let'}, {'@empty'}, ng-template and server-side rendering. The Patterns section shows how to cover the common cases with signals and directives.
