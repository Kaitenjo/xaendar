Reactivity with signals

A signal is a value that notifies whoever reads it when it changes. Signals hold the state of your components, and they are what the compiled templates subscribe to.

Three primitives

FunctionCreatesUse it for
signal(value)A writable signal: read it with count(), change it with set() or update().The state.
computed(fn)A read-only signal derived from others, recomputed lazily when they change.Values derived from the state.
effect(fn)A function that runs now, and again whenever a signal it read changes.Side effects: logging, storage, imperative DOM work.

All three are exported by {'@xaendar/core/signals'}.

Reading and writing

A signal is a function: calling it returns its value and, inside a computed signal, an effect or a template binding, registers a dependency. set(value) replaces the value; update(fn) computes the new value from the previous one. Writing a value equal to the current one, by Object.is, notifies nobody.

Signals compare values by identity. Pushing into an array, or changing a property of an object, does not change the signal: always produce a new array or object, as {'items.update(items => [...items, item])'} does.

Signals in templates

Templates read signals by calling them, exactly like the class: {'{ celsius() }'}. The compiler turns each interpolation, binding and control flow block into a binding subscribed to the signals it reads, so a change updates only the affected nodes.

Effects of a component

this.effect() creates an effect bound to the component: it is disposed automatically when the component leaves the page. Create it in onInit or afterRender.
