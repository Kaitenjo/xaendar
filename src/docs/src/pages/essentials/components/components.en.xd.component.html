Components

Components are the building blocks of a Xaendar application. Each one is a standard custom element: a TypeScript class for the logic, a template for the markup and a stylesheet scoped to its shadow root.

Defining a component

A component needs three things:

  • a class extending CustomElement, declared in a file ending with .xd.component.ts;
  • the {'@WebComponent'} decorator, with the tag name (selector) and the path of the template (templateUrl);
  • optionally a stylesheet (styleUrl), applied only inside the component.

The example below contains two components. ex-user-badge receives data through inputs and talks back through an output; ex-user-profile uses it twice. Open the files tabs to read both.

Inputs

An input is an accessor decorated with {'@Property'}. Its value is a signal: read it by calling it, name(), in the class or in the template. The decorator argument is the default value; {'@Property.required()'} marks an input the parent must always bind.

The parent binds an input like an attribute. name="Ada Lovelace" passes a static string, while {'online="{ adaOnline() }"'} passes the value of an expression, and keeps it up to date.

Outputs

An output is an accessor decorated with {'@Event'}, typed Output. Calling emit(value) dispatches a CustomEvent named after the accessor, with the value in its detail. The parent listens to it like to any DOM event: (wave)="onWave($event)".

Using a component

A template declares the components it uses with {'@import'}, so that the compiler can check the bindings against their inputs and outputs. The classes must also be imported by your JavaScript at runtime, so that the custom elements get defined.

Components are real custom elements: once defined, {''} works in any HTML page, in another framework, or created with document.createElement().
