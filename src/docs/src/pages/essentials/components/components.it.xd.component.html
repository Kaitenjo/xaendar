Componenti

I componenti sono i mattoni di un’applicazione Xaendar. Ognuno è un custom element standard: una classe TypeScript per la logica, un template per il markup e un foglio di stile confinato nel suo shadow root.

Definire un componente

Un componente ha bisogno di tre cose:

  • una classe che estende CustomElement, dichiarata in un file che termina con .xd.component.ts;
  • il decorator {'@WebComponent'}, con il nome del tag (selector) e il percorso del template (templateUrl);
  • facoltativamente un foglio di stile (styleUrl), applicato solo dentro il componente.

L’esempio qui sotto contiene due componenti. ex-user-badge riceve dati tramite gli input e comunica verso l’esterno con un output; ex-user-profile lo usa due volte. Apri le schede dei file per leggerli entrambi.

Input

Un input è un accessor decorato con {'@Property'}. Il suo valore è un signal: si legge chiamandolo, name(), nella classe o nel template. L’argomento del decorator è il valore di default; {'@Property.required()'} indica un input che il padre deve sempre legare.

Il padre lega un input come un attributo. name="Ada Lovelace" passa una stringa statica, mentre {'online="{ adaOnline() }"'} passa il valore di un’espressione, e lo mantiene aggiornato.

Output

Un output è un accessor decorato con {'@Event'}, di tipo Output. Chiamare emit(valore) invia un CustomEvent con il nome dell’accessor, con il valore nel suo detail. Il padre lo ascolta come qualsiasi evento del DOM: (wave)="onWave($event)".

Usare un componente

Un template dichiara i componenti che usa con {'@import'}, così il compilatore può verificare i binding rispetto ai loro input e output. Le classi vanno anche importate dal tuo JavaScript a runtime, perché i custom element vengano definiti.

I componenti sono veri custom element: una volta definito, {''} funziona in qualsiasi pagina HTML, dentro un altro framework, o creato con document.createElement().
