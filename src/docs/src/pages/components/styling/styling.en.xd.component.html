Styling

Each component has its own stylesheet, adopted by its shadow root: its rules match the elements of its template and nothing else, and the rules of the page do not match them. What crosses the boundary is decided by CSS itself: inherited properties, custom properties, the host element, the projected content and the parts a component exposes.

The component stylesheet

styleUrl points to a plain .css file. The plugin compiles it once into a CSSStyleSheet, which every instance of the component adopts when it is connected: a hundred instances share one stylesheet. Components pointing to the same file share it too.

Both paragraphs have the class title, and each stylesheet styles only its own: the red border stays in the parent, the uppercase stays in the child. The color and the italic, instead, reach the child: they are set on its host element, and inherited properties flow into the shadow root like into any other element.

Styling the host

Inside the stylesheet, :host matches the element of the component itself. A custom element is display: inline by default, so most components set a display here. :host(selector) matches the host only when it also matches the selector: a class, an attribute or a state set from outside.

The parent only sets a class and an attribute; the chip decides how they look. The click is handled by a single listener on the container, because a template cannot listen to native events on a component tag: see the edge cases of Outputs.

Theming with custom properties

Custom properties are inherited, so they cross shadow roots: a component can read var(--accent, fallback) and let any ancestor decide the value. This is the way to offer a theming API without exposing the internals.

Parts and projected content

An element with a part attribute can be styled from outside with ::part(name), and only that element: its children stay private. The content projected into a slot belongs to the template that wrote it, so it is styled by that template’s stylesheet; the component can add rules for it with ::slotted(selector), which only matches the elements assigned to a slot, not their descendants.

When both stylesheets style the same projected element, the outer one wins: the green of the parent beats the red of ::slotted(.note). A component’s ::slotted rules are defaults that the user of the component can override.

Dynamic classes and styles

class and style are attributes like any other: bind them to an expression and the attribute is rewritten when the value changes. Building the string in a computed signal keeps the template short and the binding reactive.

Edge cases

A binding on a native element sets an attribute, and an attribute is a string: an object becomes [object Object], and the browser ignores it. Build the string yourself.

An expression that starts with a backtick, after the space following the brace, is not parsed. Remove the space.

Only .css files are supported: Sass, Less and the others are rejected.

The stylesheet is built in the browser from the text of the file, so it has no URL of its own. An {'@import'} rule is dropped with a warning, and a relative url() is resolved against the page instead of the CSS file. Use one file per component, or share a file between components, and refer to assets with absolute paths, for example from the public folder.

The styles of the page, including resets such as box-sizing: border-box, do not apply inside shadow roots. Repeat them in the component stylesheets, or share a stylesheet file between components.
