Inheritance

Components are classes, so they can share logic through a base class: signals, computed signals and methods are inherited as usual, and templates can read them. Two things are not inherited: the template, which belongs to each decorated class, and the knowledge the template compiler has of inputs and events, which it reads only from the class of the component.

A base class for shared logic

The base class extends CustomElement and has no decorator: it is not a component, and it is never registered. Each component extends it, with its own {'@WebComponent'} and its own template.

count, atZero and the three methods live in CounterBase; the two templates read them as if they were declared in the components. Signals declared in a base class are recognized in attribute bindings too: the compiler follows the extends chain, also into other files.

The input is the exception. The base class needs step, but declares it abstract, typed as a plain function, and each component declares it with {'@Property'}: that way the compiler sees it, and checks {'step="{ 5 }"'} against its type. The plain function type matters: see the edge cases.

Extending a component

A component can extend another one. The subclass needs its own decorator, which gives it a selector and a render function; its templateUrl can point to the template of the parent.

Edge cases

Here the base class declares step with {'@Property'}, and the component inherits it. The template of the parent binds step="2", a string, and it compiles: the compiler does not know the input, so it checks nothing. At run time the input works, and receives the string: each click concatenates instead of adding. Declare inputs in the class of the component, abstract in the base class when it needs them.

The compiler collects the signal members of the whole class chain without removing duplicates, so a member that is a signal in the base class and is declared again in the component breaks the template. Unlike type errors, it makes the build fail. In the base class, give the member a type that is not a signal type.

An event declared with {'@Event'} in a base class is dispatched as usual, but a template cannot bind it: the compiler looks for it in the class of the component only. Declare events in the class of the component.

The render function belongs to the decorated class, and it is not looked up along the prototype chain. A subclass registered by hand, without {'@WebComponent'}, throws when it is connected.

Only the classes decorated with {'@WebComponent'} must be in .xd.component.ts files. A base class without decorator can live in any file, as counter-base.ts does.
