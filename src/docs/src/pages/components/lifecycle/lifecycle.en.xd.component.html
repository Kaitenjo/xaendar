Lifecycle

A component is rendered when its element is connected to the document and torn down when it is disconnected. Three optional methods let you run code at those moments: onInit, afterRender and onDestroy. They run at every connection and disconnection, not once per element.

The hooks

HookWhenUse it for
constructor Once, when the element is created. Rarely needed: fields are initialized here anyway.
onInit() At every connection, before the render. Effects, timers, listeners on window or document.
afterRender() At every connection, after the render. Work on the elements of the template: focus, measures, canvas, third-party libraries.
onDestroy() At every disconnection, before the template is removed. Undoing what onInit did outside the component.

Parents and children

A child component is connected while its parent renders its template. So the child runs its whole sequence, from onInit to afterRender, in the middle of the sequence of the parent, and before the parent binds anything to it.

Add the parent and read the log from the top: the parent starts, the child runs all its hooks with the default label, then the parent finishes. The effect of the child runs again a moment later, when the bound label arrives: it is the only place where the child sees it. Changing the label re-runs only the effect. Removing the parent calls onDestroy on the parent first, then on the child, and disposes the effect of the child.

Edge cases

Moving an element is a disconnection followed by a connection, so it goes through the whole lifecycle:

  • onDestroy, onInit and afterRender run again, as the log shows;
  • the template is rendered from scratch: the text typed in the field is lost, because it lived in the old DOM;
  • the signals of the instance survive: the counter keeps its value;
  • the effect created in a field is disposed at the first move and never created again, so it stops following the counter, while the one created in onInit is created again at every connection.

They work until the first disconnection, then they are gone for good. Create effects in onInit, unless the element is never moved or reattached.

The base class uses the callbacks of custom elements to render the template, and keeps them private. Defining them in a component does not compile, and at run time would replace the ones of the base class: the template would never be rendered. Use the hooks.

An element rendered by a template is removed by that template only while it is still where the template put it. If you move it somewhere else, it stays there when its {'@if'} or its {'@for'} row goes away, no longer bound to anything. Move only the elements you created yourself, as the example does. Inputs are not attributes, so the base class declares no observedAttributes: read inputs reactively instead. See Inputs.

API summary

APIDescription
onInit()Runs at every connection, before the render.
afterRender()Runs at every connection, after the render and the start of the view queries.
onDestroy()Runs at every disconnection, before the effects are disposed and the template is removed.
this.effect(fn, options?)An effect disposed at the next disconnection. Returns a function that disposes it earlier.
