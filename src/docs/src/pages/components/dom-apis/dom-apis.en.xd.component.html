Using DOM APIs

Templates cover most of the DOM work, but not all of it: drawing on a canvas, moving the focus, measuring elements, driving a library that knows nothing about signals. For those, a component combines three tools: a query to reach the element, a lifecycle hook to know when it exists, and an effect to keep it in sync with the state.

Drawing from the state

An effect created in afterRender runs once the template exists, and again whenever a signal it reads changes. It is disposed when the component is disconnected, and created again at the next connection, with the new elements.

The effect reads values and color, so each button redraws the chart exactly once. Nothing else in the component knows about the canvas.

Reacting to elements that come and go

A query is a signal, so an effect reading it runs again when the element appears or disappears. Created in onInit, the effect follows the element for the whole life of the component.

Edit only changes a signal: the {'@if'} renders the field, the query finds it, and the effect focuses it. The same pattern works for scrolling an element into view or starting an animation.

Observers

ResizeObserver, IntersectionObserver and MutationObserver connect to elements of the template in afterRender and disconnect in onDestroy. Their callbacks write signals, and the template does the rest.

Listeners on window or document follow the same rule: add them in onInit and remove them in onDestroy, through a stable reference. Listeners on elements of the template need no cleanup: they go away with the elements.

Custom elements from other libraries

A template accepts only Xaendar components as custom elements, so an element from another library has to be created in code: in afterRender, inside an element of the template, with an effect copying the state into its properties.

The gauge is a plain HTMLElement with a value property, as a component of any other library would be. The effect sets the property, not an attribute, so any type of value can be passed. The gauge is created with new VanillaGauge(): with document.createElement the class would be used only as a type, TypeScript would drop the import, and the element would never be defined.

Edge cases

Every tag with a hyphen in a template must be an imported Xaendar component, so the tag of the gauge cannot be written in the template. See Selectors and registration.

An attribute bound in the template is written again whenever its value changes: a class added with classList to an element whose class is bound is gone at the next update. Change the state the binding reads instead, or touch only what the template does not bind. Elements created or changed in code belong to one render: moving the component renders its template again, and whatever afterRender built has to be built again, as the examples above do. See Lifecycle. The template removes an element only while it is still where the template put it. Move or remove only the elements you created yourself.
