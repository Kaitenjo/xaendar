Outputs with {'@Event'}

An output is how a child talks to its parent. You declare it with {'@Event'} on an accessor of the child, and it becomes an Output whose emit dispatches a CustomEvent on the element of the child. The parent listens to it in its template, like to a native event.

Declaring and emitting

The event is named after the accessor, and the type argument of Output is the type of its detail. Without a type argument the event carries no detail, and emit takes at most the options. The options passed to the decorator apply to every emission; those passed to emit are merged over them for that emission only.

Listening in the parent

The parent binds a method to the event with (valueChange)="setQuantity($event)". $event is the CustomEvent itself: the method reads the value in event.detail.

The picker never changes the quantity: it shows its input and asks for a new value with valueChange. The parent owns the quantity and decides: past 5 it ignores the request, and the picker keeps showing the value it receives. Together, an input and an output make a component controlled by its parent, which is how Xaendar replaces two-way binding. cleared has no detail, and its handler takes no argument: a template passes $event only to the events that carry a detail.

Event options

By default the event is dispatched on the element of the child and goes no further: only the listeners on that element receive it. bubbles lets it climb through the ancestors, but only within the shadow root containing the child; composed lets it cross shadow roots, up to the document. cancelable lets a listener call preventDefault(): see the edge cases.

Press the four buttons. The template binding on the tag receives everything. bubbling reaches the frame, which is in the same shadow root as the child, but stops at the root, so the host of the parent never sees it. Only escaping, and plain with the options overridden, reach the host and the document. On the way out the target is retargeted: the document sees the outermost component containing the source, while composedPath()[0] is still the element that emitted it.

The frame, the host and the document listen with addEventListener: a template can only bind a custom event on the tag of the component that declares it. Listeners added outside the template are yours to remove, which the example does in onDestroy.

Edge cases

The child is connected, initialized and rendered before the parent attaches its listeners, so the events it emits from onInit and afterRender reach nobody. An event emitted a microtask later arrives, and so does the one emitted from onDestroy: the listeners are still in place while the child is removed. To tell the parent that the child is ready, emit after a microtask, or let the parent read the state of the child through a query.

emit tells a detail from the options by looking for a key named bubbles, cancelable or composed. A detail with one of those keys is taken as the options, whatever the value of the key: the event has no detail, and the key sets the option. Wrap the value in another object, as bookedWrapped does. The behavior is listed in Known issues.

emit returns nothing, so the child cannot know whether a listener called preventDefault(). To make a cancelable event useful, declare it with {'@Event'}, so that templates can listen to it, and dispatch it yourself with dispatchEvent, which returns false when the event was canceled. Listeners run synchronously, so the result is ready on the next line. The event has a detail, the mode of the note, so that the parent receives $event and can cancel it.

For an Output without a type argument the template compiler declares no $event: the handler can only be called without it. When the parent needs the event itself, to cancel it or to read its target, give the event a detail.

The name of the event is the name of the accessor, letter by letter. HTML attributes are case-insensitive, but event bindings are not: (valuechange) does not match valueChange.

On a native element a template can only bind the events of HTMLElementEventMap, so it cannot catch a bubbling custom event on an ancestor of the child. Add the listener with addEventListener, as the frame does in the second example.

The tag of a component accepts only the events it declares: (click) does not compile. Listen on a native element around it, since the native events that are composed, like click, leave the shadow root of the component; or emit an event of your own from inside.

The template compiler only sees the events declared in the class of the component: binding an event declared in a base class fails with the same Unknown event error. See Inheritance.

A component is an HTMLElement, so an event named remove, click or focus would replace a method of the element. TypeScript rejects it, and so it does for an input or a signal named title, lang or hidden. Choose another name, or keep the name in templates with an alias.

{'Output'}The type of the accessor: T is the type of the detail, void by default.
emit(detail, options?)Dispatches the event on the element, with options merged over the default ones.
