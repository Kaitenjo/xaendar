Content projection with slots

The elements written between the tags of a component are not rendered inside it: they stay where they are, as children of the element, and the component shows them through the {''} elements of its template. Xaendar adds nothing to the standard slots of the shadow DOM, so everything you know about them applies.

Default slot, named slots and fallback

A {''} without a name receives every child without a slot attribute. A {''} receives the children with slot="header". The content of a slot is its fallback, shown while nothing is assigned to it.

The second card fills only the default slot, so its header shows Untitled. The footer of the first card is projected inside an {'@if'}: projected content is part of the template of the parent, with its conditions, its loops and its bindings. The button in the footer calls a method of the parent and shows a signal of the parent; the card only decides where it appears.

Choosing the slot at run time

slot is an attribute like any other, so it can be bound to an expression: the browser moves the element to the new slot when the value changes. An element whose slot matches no slot of the component is not shown at all.

On nowhere the note disappears, but it is still a child of the split view: its bindings keep running, and it shows up again as soon as its slot matches.

Forwarding slots

A component can pass its projected content on to a child component: it puts a {''} among the children of the child, with a slot attribute choosing where it goes.

The second panel receives no title, and shows Panel fallback, not the Untitled of the card: the card receives the slot of the panel, so for the card its header is never empty.

Edge cases

The component is rendered before the parent creates its children, so in afterRender its slots are still empty. The children arrive right after, and every change is announced by slotchange, which a template can bind on the {''} element. To read the projected elements reactively, use a content query.

In plain HTML the spaces and line breaks between the tags of a component are text nodes, assigned to the default slot, so the fallback disappears. A Xaendar template creates no text node for whitespace, and the anchors of {'@if'} and {'@for'} are comments, which are never assigned: as long as nothing visible is projected, the fallback shows. The component cannot read the projected elements through its template, nor style them beyond ::slotted(): they are elements of the template of the parent, styled by its stylesheet. See Styling.

API summary

SyntaxDescription
{''}The default slot: the children without a slot attribute.
{''}A named slot: the children with slot="x".
{'fallback'}Shows its content while nothing is assigned to it.
