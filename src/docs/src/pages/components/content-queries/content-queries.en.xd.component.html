Content queries

A content query finds elements among the content projected into the component, instead of its own template. It is how a component works with children it does not render: a tab group with its panels, a list with its items, a form with its fields. Like view queries, the result is a signal that follows the changes of the content.

Querying the projected content

{'@Query.content'} and {'@Query.content.all'} take the same targets as view queries, a CSS selector or the class of a component, and look into the elements assigned to the slots of the component, together with their descendants.

The group renders one tab for each panel it finds, with the label the panel received from the parent, and tells each panel whether it is active through a signal of the panel: the query is typed by the class, so the group can reach the public members of the instances. Add a panel: the parent renders it inside the group, the query finds it, and a new tab appears.

Which slots, which elements

By default a content query looks into every slot. slots restricts it to one slot, or to a list, where the empty string is the default slot; lightDom: true looks instead at all the children of the element, assigned to a slot or not. The two options cannot be combined.

  • the results follow the slots in the order of the template, then the order of assignment: aside comes first in the inspector, so B comes before A, even though A comes first in the parent;
  • descendants count: C is inside a div assigned to the default slot;
  • D is assigned to no slot: only lightDom finds it, in document order;
  • E is the fallback of a slot: it belongs to the inspector, and no content query finds it.

Queries without decorators

querySlot and querySlotAll are the functions behind the decorators, as query and queryAll are for view queries, with the same caveat in attribute bindings.

Edge cases

The wrapper projects its own slot into the counter. The query of the counter does not see that slot but what it carries: the items written in the outermost template, then the item of the wrapper. Nested slots are flattened.

The projected content is created by the parent after the component has rendered, so in afterRender a content query is still empty. Read it reactively, in a computed signal or in an effect, as the tab group does. See the edge cases of Content projection. A content query is updated when elements are added or removed, when their slot attribute changes and when the slots of the component change. A change to any other attribute, such as a class, does not update it, as for view queries.

API summary

APIDescription
{'@Query.content(target, options?)'}The first projected element matching target, or null.
{'@Query.content.all(target, options?)'}All the projected elements matching target.
{"{ slots: 'name' }"}, {"{ slots: ['', 'name'] }"}Only the given slots; '' is the default slot.
{'{ lightDom: true }'}All the children of the element, assigned to a slot or not.
querySlot(this, target, options?), querySlotAll(…)The same queries, created in a field.
