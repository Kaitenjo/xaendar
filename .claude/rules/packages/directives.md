# @xaendar/directives

The built-in directives: `AnimationDirective` (`@@animation(enter="…" leave="…")`), whose `enter` and `leave` are a CSS class or a function (`ElementAnimation`), `''` for no animation on that side, plus `ignoreReducedMotion`; `InnerHtmlDirective` (`@@innerHtml(html="…")`), with `options` (`HtmlSanitizerOptions`), `sanitizer` and the event `sanitized`; `sanitizeHtml` and `trustHtml`; `ClassDirective` (`@@class(value="…")`, `ElementClasses`) and `StyleDirective` (`@@style(value="…")`, `ElementStyles`), Angular's `ngClass`/`ngStyle`. `@xaendar/core` is a peerDependency, `@xaendar/common` a dependency (external, shared with core).

- `@@class` and `@@style` only declare a private getter with `@HostAttribute('class')` / `@HostAttribute('style')`, which converts `value` into a string (`utils/element-classes`, `utils/element-styles`): core merges it with the other sources of the attribute (template > directives > component), removes the keys it no longer holds, writes it on the server (`_applyHostAttributes`) and takes it away when the directive is destroyed. `toStyleString` converts the keys with `toCssPropertyName`, checks the units against `CSS_UNITS`, throws on a key that is neither, and leaves out a declaration that `parseStyleDeclarations` does not read back as itself (a `;` in the name or the value).

- A Xaendar library (`"xaendar": { "library": true }`): `build-projects` builds it with `xd build` of the CLI, run from its sources in a workspace of its own (`dist/.xaendar-library-<folder>/xaendar.json`, deleted afterwards), into `dist/@xaendar/directives` with `xaendar-manifest.json`, after `core`. `buildLibrary` reads `tsconfig.json`, which leads `@xaendar/*` to the builds in `dist` (`skipLibCheck`: their declarations declare the global `Signal` several times): the editor needs `npm run build:projects` once; the specs and `typecheck:projects` use `tsconfig.spec.json`/`tsconfig.typecheck.json` on the sources.
- The specs run in the `directives` project of the root Vitest, whose `createBabelPlugin` (`packages/cli/src/utils/babel-plugin`) transpiles the decorators as `xd test` does. `*.directive.ts` stays out of the coverage: Babel gives each `accessor` a setter that `@Property` replaces, never called. The behavior lives in `utils/element-animation` (`enterElement`, `leaveElement`), tested there; the class reads its inputs, and registers `onLeave` only when `leave` holds an animation as it starts.
- `enter` on the server (no `getComputedStyle`) only adds the class, so the browser animates the HTML of the server; in the hydration `playClass` finds the class, which restarts nothing, and waits for its end. `leave` goes through `onLeave` of core, a no-op on the server.
- The end of a CSS animation is `AnimationEnd` (`models/animation-end`): the events of the element itself, the longest `elapsedTime`, a cancel, or the CSS times (`readAnimationTimes`) plus `END_MARGIN`.
- `sanitizeHtml` needs no DOM, so the server and the browser write the same HTML: `HtmlTokenizer` (`models/html-tokenizer`) reads the tokens as the HTML parser does (raw text, comments, bogus markup, a tag cut by the end dropped), `HtmlSanitization` (`models/html-sanitization`) writes back only what the policy keeps, well formed (texts and values encoded, `&` kept, every element closed, implied ends, end tags without start dropped), so that a different tokenization can only lose content. URLs are checked by `utils/url-sanitizer` after decoding the references that can hide a scheme. Defaults are Angular's `VALID_ELEMENTS`/`VALID_ATTRS` plus `aria-*`. The policy of each options object is cached in a `WeakMap`. `utils/inner-html` (`renderHtml`) writes `innerHTML` through the Trusted Types policies `xaendar#inner-html` and `xaendar#inner-html-unsafe`; the directive writes it in `onInit` on the server, in an effect in the browser.
