# @xaendar/directives

The built-in directives: `AnimationDirective` (`@@animation`), `InnerHtmlDirective` (`@@innerHtml`) with `sanitizeHtml` and `trustHtml`, `ClassDirective` (`@@class`), `StyleDirective` (`@@style`), `ComponentOutlet` (`@@componentOutlet`). `@xaendar/core` and `@xaendar/internals` are peerDependencies, `@xaendar/types` a dependency (external, shared with core).

## Build and specs

- A Xaendar library (`"xaendar": { "library": true }`): `build-projects` builds it after `core` with `xd build`, from its sources in a temporary workspace (`dist/.xaendar-library-<folder>/xaendar.json`), into `dist/@xaendar/directives` with `xaendar-manifest.json`. Its `tsconfig.json` leads `@xaendar/*` to the builds in `dist` (`skipLibCheck`: they declare the global `Signal` several times), so the editor needs `npm run build:projects` once; specs and `typecheck:projects` use `tsconfig.spec.json`/`tsconfig.typecheck.json` on the sources.
- Specs run in the `directives` Vitest project, transpiled by `createBabelPlugin` as `xd test` does. `*.directive.ts` is out of the coverage (Babel's accessor setters are never called): put the behavior in `utils/`/`models/` and test it there.

## Directives

- `@@animation`: behavior in `utils/element-animation` (`enterElement`, `leaveElement`); `onLeave` is registered only when `leave` holds an animation at start. On the server `enter` only adds the class (the browser animates the server HTML; `playClass` restarts nothing at hydration). A CSS animation ends by `AnimationEnd` (`models/animation-end`): the element's own events, the longest `elapsedTime`, a cancel, or the CSS times plus `END_MARGIN`.
- `@@class`/`@@style` only declare a private `@HostAttribute('class'|'style')` getter converting `value` to a string (`utils/element-classes`, `utils/element-styles`): core does the merging, removal, server writing and cleanup. `toStyleString` converts keys with `toCssPropertyName`, checks units against `CSS_UNITS`, throws on anything else, and drops a declaration `parseStyleDeclarations` does not read back as itself.
- `@@componentOutlet` calls `createComponent` in an effect of `onInit` (`options` typed `CreateComponentOptionsWithOptionalTarget`), destroying the previous `ComponentRef` first, and in `onDestroy`. A new `options` object recreates the component.
- `sanitizeHtml` needs no DOM, so server and browser write the same HTML: `HtmlTokenizer` tokenizes as the HTML parser does, `HtmlSanitization` writes back only what the policy keeps, well formed, so a different tokenization can only lose content. URLs are checked by `utils/url-sanitizer` after decoding references that can hide a scheme, on the URL helpers of `@xaendar/internals`. Defaults are Angular's `VALID_ELEMENTS`/`VALID_ATTRS` plus `aria-*`; each options object's policy is cached in a `WeakMap`, after `assertSafeOptions` rejects what always runs code (`script`/`base`/`meta`, `on*`/`srcdoc`, `javascript`/`vbscript`, prefixes matching them included). A kept SVG animation never targets `href` (`isSafeAnimationTarget`). A URL loading a resource (`isResourceUrlAttribute`) is kept only from the application or a `trustedOrigins` of the project (`isTrustedResource`, `_SECURITY` of core read once into `HtmlSanitizerPolicy.trustedOrigins`, `null` when `resourceUrls` is `'off'`), as the templates check it. The options of the application, set by `setHtmlSanitizerOptions` (checked by `assertSafeOptions`, emptying the cache of the policies), are the policy without options, and are joined with the options of a use (`joinOptions`: lists added, `urlSchemes` replaced); `assertSafeOptions` uses `describeUnsafeSanitizerOptions` (`utils/html-sanitizer-options`). They are not in `xaendar.json`: the application sets them in its code. `renderHtml` (`utils/inner-html`) writes through the Trusted Types policies `xaendar#inner-html` and `xaendar#inner-html-unsafe` (`toTrustedHtml` of `utils/trusted-html`: the policies live in that module and are never exported, since their `createHTML` keeps the HTML as it is; `trustedTypes` is declared by core), in `onInit` on the server and in an effect in the browser.
