# @xaendar/ssr-compiler

`compileServer(input, options)` compiles a template into the functions rendering it on the server: parsed by `compiler`, `@import`s resolved when `templateDir` is given, generated by `ServerGenerator`. Depends on `common`, `compiler`, `types` (not on `core` nor `ssr`: the generated code imports them). Used by `build-tools` in Vite's server environments; built with tsup.

- The states under `server-generator/states/` mirror the client generator's, on the internals `compiler` exports. Every scope (`render`, `@if`/`@switch` branches, `@for` body, content of an element with structural directives) is a function called as `key.call(this, out, context, …)`, with the client's layouts (`_scope(parentContext, _layoutN)`, `_read(context, depth, slot)`; root `_scope(null, _layout0, undefined, this)`). Declared `<template>`s are module functions taking no slot: `_ssrRenderTemplate(out, context, template_row_12, depth, [args])` climbs `depth` scopes.
- Shared with the client generator, change both together: `getTextSeparators` (where `_generateNodes` writes `<!---->`), `isLastRenderedChild` (`ServerParent.end`: the last block writes no closing marker, since the client renders it without anchor), the `@for` track (key of `_ssrItemMarker`), `mapContentTemplates`, the styling utils.
- The hydration markers are string literals from `costants/ssr-markers.constants.ts`, mirroring core's `_SSR_MARKERS` (this package depends on no runtime). `@client` and `@defer` write only their markers and `@placeholder`.
- Static text and attributes are escaped at compile time; expressions go through `_escapeText`, `_ssrAttribute` (whole attribute, omitted for `null`/`undefined`) or `_escapeRawText`. Browser globals are read through `globalThis` (`SERVER_RESOLVE_OPTIONS`): `undefined` instead of throwing.
- As on the client, what never varies is a module constant (`div0$element` for `_ssrStartTag`/`_ssrComponent`/`_ssrIsland`/`_ssrClientComponent`, `div0$structural`), descriptor expressions and the track are module functions (`declareExpression`); expressions inline in a function body stay inline, read once. `@case` values become a constant array (`case0_1$values`, `indexOf(__value) !== -1`).
- Template variables are values read once: a `@let` is `_set(context, 0, slot, value)`, parameter defaults are expressions (`declareTemplateParameters` with `server`). Element refs are `undefined`.
- Imported components and directives (`addImportedMetadata`) get their inputs by property name; client-only ones (`isClientComponent`) are written with `_ssrClientComponent`, whatever the class on the server. `islands` lists the interactive components a static template renders (`_ssrIsland`). A native element's custom directives (`mapDirectives`: selector and properties, no events) go to `_ssrStartTag`; a branch holding only a directive is not empty; a component's custom directives are left out.
- `getServerDependencies` keeps every module, unless the template holds a `@client`, a `@defer` or a client-only component: then only the modules declaring what the server renders.
- `generate` writes `render.events` for the event contract (`keydown` for `keydown.enter`: the replayed event keeps its key) and `data-xd-submit` (core's `_SUBMIT_ATTRIBUTE`) on elements or branches with `(submit)`.
- `@try` → `_ssrTry(out, context, tryN, catchN)`; `@render` of an expression → `_ssrRenderTemplateRef`; a standard `<template>` writes its `content` as is.
